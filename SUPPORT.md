# Support

Use the public issue tracker for reproducible, non-sensitive Hivemind questions
and troubleshooting. Choose the support issue form when you need help using a
released snapshot; use the bug report form when you can demonstrate a defect.

## Include enough context

Please provide:

- the Hivemind version, tag, or commit;
- the deployment shape and relevant operating-system/runtime versions;
- the command or request that shows the problem;
- expected and observed behavior;
- redacted logs and a minimal reproducer, configuration, or test where useful.

Never post tokens, passwords, private data, or undisclosed vulnerability
details. Redact ordinary support material before opening an issue. The project
does not advertise a separate private support inbox; if a support question
cannot be safely redacted, do not publish it.

## Security and conduct

Do not use a public issue for a suspected vulnerability. Follow the
[security policy](SECURITY.md) and open a
[private GitHub Security Advisory](https://github.com/Lesur-ai/hivemind/security/advisories/new).
This advisory form is the repository's concrete private GitHub route; never
include vulnerability details in a public channel.

For harassment, doxxing, threats, or another conduct concern, use
[GitHub's abuse-reporting form](https://support.github.com/contact/report-abuse)
and include links to the relevant repository content. The project does not
advertise a separate confidential conduct inbox. See the
[Code of Conduct](CODE_OF_CONDUCT.md) for the behavior and enforcement scope.

## What to expect

Support is provided on a best-effort basis. Maintainers may ask for a current
version, a smaller reproducer, or a confirmation that credentials and personal
data have been removed. Public `main` represents released source; accepted
fixes and improvements are evaluated for a subsequent release snapshot.
